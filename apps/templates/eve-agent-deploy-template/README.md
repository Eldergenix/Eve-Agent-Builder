# eve Agent Deploy Template

This is the public, service-owned deployment template for agents generated by eve Agent Builder.

It contains only the standalone runtime shell, chat frontend, and deployment scripts. It does not include the hosted builder UI or builder source code.

## How it works

1. The builder creates a public `EVE_AGENT_CONFIG_URL` for a single generated agent.
2. The platform deploy button clones this template.
3. `scripts/materialize-agent.mjs` fetches the config URL before install/build where the platform allows it.
4. The script writes `agent/`, `evals/`, optional service helpers, deployment notes, and platform manifests.
5. Next.js runs with `withEve()` and serves the chat UI plus eve endpoints.

Materialization rewrites `.env.example` so each generated agent only asks for the credentials selected in Agent Builder. Cloudflare targets also get `.dev.vars.example`, `wrangler.jsonc`, and `open-next.config.ts`.
Vercel, Railway, and Docker run materialization before dependency installation when `EVE_AGENT_CONFIG_URL` is present, so the installed package set matches the generated agent.

## Required variable

```sh
EVE_AGENT_CONFIG_URL=https://builder.example.com/api/deploy/config?payload=...
```

Users still provide their own model/provider, observability, database, and cache API keys in the target platform.

## Deploy buttons

- Vercel can receive `EVE_AGENT_CONFIG_URL` as a non-secret default in the deploy button URL.
- Cloudflare clones this public template repository through Deploy to Cloudflare; paste `EVE_AGENT_CONFIG_URL` when configuring variables.
- Railway needs this repository published as a Railway template; paste `EVE_AGENT_CONFIG_URL` when configuring variables.

When the generated agent enables Cloudflare-native services, materialization writes the selected Wrangler bindings for D1, KV, R2, Vectorize, Queues, Hyperdrive, Workers AI, Browser Rendering, Analytics Engine, Images, and AI Search.
D1, KV, and R2 are emitted as binding-only declarations so Deploy to Cloudflare can provision those resources during deployment.

## Local test

```sh
pnpm run materialize
pnpm install
pnpm dev
```

If `EVE_AGENT_CONFIG_URL` is not set, `pnpm dev` and `pnpm build` use the checked-in fallback agent.
